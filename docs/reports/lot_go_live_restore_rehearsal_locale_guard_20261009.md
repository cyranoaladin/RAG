## Changement

Le runbook impose désormais un nom de projet Compose en minuscules, un fichier d'environnement existant désigné explicitement, `--locale=C --encoding=UTF8`, et la comparaison en lecture seule de l'encodage et des locales source/cible **avant** `pg_restore`. Après restauration, il compare les têtes, les comptes, les identités de lignes et `text_tsv`. Le test exécute réellement le garde avec une cible compatible, une cible `SQL_ASCII`, une cible `en_US.utf8`, une source non conforme et une réponse vide. Le contrôle documentaire existant des rôles runtime est rendu indépendant de la longueur du runbook.

Validation du correctif : `python3 scripts/tests/test-go-live-evidence-refresh.py` : 15 tests réussis ; syntaxe Bash du bloc de restauration : sortie 0 ; `docker compose config --quiet` sur la fixture extraite avec des valeurs de test : sortie 0, services exactement `pgvector` et `restore-migrator`. Le bloc SQL exact des empreintes a été rejoué en lecture seule sur staging : head 5/20, 11 collections, 315 artefacts, 479 placements, 8 268 chunks et 8 268 valeurs `text_tsv`, sortie 0. Cette lecture ne remplace pas une nouvelle restauration au SHA final.

Cette preuve porte sur le staging et le code de `main` ci-dessus ; l'image API staging n'était pas encore reconstruite depuis ce checkout. `final_release_proof=false`. Une preuve fraîche reste requise au SHA final et sur la cible production qualifiée avant go-live. Aucune base ou service de production n'a été modifié.
