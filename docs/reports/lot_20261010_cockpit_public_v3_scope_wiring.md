# Lot Cockpit — câblage strict des scopes étudiants V3 publics

Date de vérification : 2026-10-10 UTC. Base de travail obtenue par `git fetch origin main`, puis worktree neuf sur `origin/main=744764c7dbc15143f88fd410d534d0a4c956e329` (tree `161eaf51bd54cc4fe4830c0d3715cb7f33162c82`). Dépendances Node installées dans ce worktree par `npm ci`. Aucun staging ni production n'a été modifié.

Le Cockpit de cette base signe encore le scope pilote maths/NSI. Le nouveau mode explicite `NEXUS_COCKPIT_SCOPE_MODE=public_v3` sélectionne exactement un scope V3 par identité signée, avec une seule matière et une seule collection. L'index JSON est embarqué dans l'image et son SHA-256 **sur la sérialisation JSON canonique** doit égaler `NEXUS_COCKPIT_PUBLIC_SCOPE_INDEX_SHA256`. Les onze entrées attendues doivent être des artefacts V3 de production, à visibilité `public` et droit `public_allowed` unique, cohérents avec leur sujet curriculaire, uniques par identifiant et collection, et autoriser explicitement le rôle `student`. La valeur historique `officiel_public` des PDF internes est refusée dans ce mode ; elle ne prouve pas les droits des dérivés publics. Le jeton interne lie le scope, son digest et la seule collection autorisée ; la vérification et la rotation rejettent toute dérive. L'API BFF garde le filtre par matière signée et la contrainte mono-collection pour `student`. Aucun élargissement de `student` vers `internal` n'est introduit.

L'index embarqué dans cette PR vaut volontairement `[]` : **aucun scope public final n'a été émis**. Par conséquent, `public_v3` refuse l'authentification, la signature de session de qualification et `/api/health` avec HTTP 503. Le mode pilote historique reste disponible hors activation explicite du mode public ; il ne peut pas servir de repli quand `public_v3` est demandé. Le SHA de build est désormais exposé par `/api/health` et transporté dans l'image Docker par `SOURCE_COMMIT_SHA`. En mode `public_v3`, son absence ou sa mauvaise forme rend aussi la health rouge ; un test a observé le refus 503 après avoir d'abord obtenu 200 avant ce correctif.

Les tests ont d'abord échoué sur l'absence de sélection V3, sur la possibilité pour le script de qualification de signer malgré un index vide, sur l'absence de `build_sha`, puis sur la mutabilité du scope. Ils passent après les correctifs. Une régression intermédiaire sur la restriction par matière signée a été détectée par les tests existants et corrigée avant validation. Un test de transport avec onze scopes **synthétiques confinés au test** vérifie la signature mono-collection, les refus du rôle enseignant et du profil multi-matière, ainsi que le rejet d'un digest d'index altéré. Ces fixtures ne sont ni des scopes émis ni une preuve E2E.

Après l'intégration de #323 dans cette branche, deux cycles RED→GREEN ont aligné le serveur et le générateur de jetons sur `public_allowed` et sur la convention d'identifiant `student_public_*_v1` scellée dans le preparation-index #323. Les tests refusent `officiel_public` et les identifiants `prod_*` hérités des scopes internes, puis exercent le vrai script CLI avec un index synthétique temporaire de onze scopes ; ils ne qualifient toujours aucun scope réel. La production d'artefacts V3 avec un rôle `student` explicite reste une dépendance de #294.

Vérifications locales finales sur ce worktree : `npm ci`, `npm run contracts:check`, `npm run lint`, `npm run typecheck`, `npm test -- --run` (216 tests passés, un ignoré), `npm run build` et `git diff --check` réussis. Le contrôle npm de la base communiqué séparément relève `npm audit --omit=dev --json` exit 0, high=0, critical=0 ; l'audit complet garde sept avis high dans les dépendances de développement et exit 1. Aucun changement de lockfile ne fait partie de ce lot.

Reste à faire avant toute ouverture du produit étudiant : finaliser et approuver la release publique successeur ; émettre onze scopes V3 réellement liés aux sujets finaux et gouvernés par #294 ou son successeur ; intégrer ces seuls artefacts et l'index dans un SHA final du dépôt ; régler `public_v3` et son digest canonique dans la cible de qualification ; construire l'image depuis ce SHA ; exécuter le harnais #293 et l'E2E étudiant réel. La configuration de qualification locale devra fournir le mode et le digest au script `mint-session-token.mjs`. Tant que ces dépendances manquent, la PR reste draft et `STUDENT_PUBLIC_PATH_PASS=false`.
